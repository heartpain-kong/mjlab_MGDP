这一屏到底是什么

把 TensorBoard 里的一条曲线当成一张行情图：横轴是训练步（不是日期），纵轴是指标值（不是价格）。 每次刷新读的是你本机的 events.out.tfevents*，没有任何联网请求。

图上的词

轮次 / 城市
一个训练 run（logs/rsl_rl/<实验>/<时间戳_run名>）。左边那一列就是自选列表，和你收藏城市是一个手感。
指标 / 品种
一条 scalar，比如 Train/mean_reward。换指标 = 换一只股票，整张图连同盘口、流水一起换掉。
分时
原始记录点直接连起来，就是 TensorBoard 里那条线。点太多时按顺序等分取均值，形状不变。
蜡烛 / K 线
把连续若干个记录点按训练步切成窗口：开盘＝窗口里第一个值，收盘＝最后一个值，细线两端＝窗口里的最高 / 最低。一根蜡烛告诉你「这一段训练里指标在多大范围内抖」。
短K / 中K / 长K / 全程K
窗口宽度的四档预设，按这个轮次的总步数自动取整成 1/2/5×10ⁿ 步。窗口越宽噪音越少、越能看出趋势。
均线 MA5 / MA10 / MA20 / MA60
最近 5 / 10 / 20 / 60 根蜡烛收盘价的平均，用来判断大方向。数字越大越平滑。
波动柱 / 成交量
下面那排柱子，口径在顶栏切：窗口振幅（最高−最低）、标准差、记录点数、相对变化。柱子高＝这一段训练抖得厉害。
基准线（灰色虚线）
图上第一根蜡烛的开盘值，相当于行情里的「昨收」。涨跌幅都是跟它比的。
未收盘的最后一根
训练还在写日志时，最后一个窗口没满，那根蜡烛会继续长 —— 和股票软件里今天那根一样。
叠到主图
副图那条线用最外侧的刻度画到主图上，方便看两个指标是不是同涨同跌。

右边那两栏

最近 5 根高低
最近五根蜡烛的最高和最低，上下一对照就知道这一段是在收敛还是在震荡。
逐点流水
最近每个记录点的步数、值、和上一点的差。找「哪一步突然跳」就看它。

键盘和链接

↑ / ↓
在轮次之间上下切换（抽屉打开、或者光标在输入框里时不生效）。
Esc
关闭抽屉 / 退出全屏。
滚轮 · 拖动 · 双击
缩放主图（以光标为锚点）、左右平移、复位。
深链接
?run=V10_seed42&tag=Curriculum/terrain_levels/level_mean&period=long&overlay=1 可以直接打开某个视角，方便发给别人；?drawer=compare 会直接打开某个抽屉。

上面那几个按钮

📊 全部指标
按分组列出这个轮次的全部 scalar。点名字换主图，点「副」换副图。
🧭 轮次对比
所有轮次 × 关键指标的一张表。⚠️ 跨轮次比较务必取同区间：这套任务的指令范围课程会在 iteration 5000 附近放宽，之后误差类指标会台阶式变差。
🧪 数据体检
NaN、常量占位、异常台阶、时间断档、采样过稀 —— 逐条列出来，附上出问题的 step。
📚 指标词典
每个指标的中文名、取向（越大越好 / 越小越好）和一句话解释。
⬇ 导出K线
把当前指标按当前窗口导出 CSV，列是 run / tag / 窗口 / 开高低收 / 均值 / 标准差 / 点数 / 起止时间。
🎬 回放
从第一根开始逐根长出来，看训练早期是怎么抖过来的。

数据从哪来

曲线
本机 logs/rsl_rl/ 下的 event 文件，由 tensorboard 的 EventAccumulator 读取，第一次读会建缓存（logs/kline_cache/），之后秒开。
缓存什么时候失效
缓存头记着源文件的修改时间和大小，文件一变就自动重读；只想让它重扫目录的话点「🔁 重扫目录」。
其它数据源
启动时可以用 --logdir 多加几个目录（比如归档到别处的训练数据），多个目录的轮次会并排列出来。

一句话：把「训练步」当日期、把「指标值」当价格。红＝这一段在涨，绿＝在跌，蜡烛＝一个窗口，均线＝滑动平均。 · 本地面板 v1.0.0

(｡•́︿•̀｡) 那个……有几件事得先说清楚

这不是行情软件，是个给训练曲线套了层炒股软件皮的本地小玩具。 横轴的「步」是训练的 iteration，纵轴的「价格」是 TensorBoard 里的 scalar。红涨绿跌只是配色。

✧ 它不会替你下结论
  • 「涨」只表示这个数在变大，不表示变好了。误差、损失、失败率涨了都是坏事。
  • 蜡烛的开高低收是窗口内的统计量，不是某一步的真实价格；窗口切换会改变形态，这很正常。
  • 跨轮次比较务必取同区间：这套任务的指令范围课程在 iteration 5000 附近放宽，之后误差类指标会台阶式变差。
  • mjlab 的 metrics 不做 dt 缩放，记录的是每步原始值的和；拿 velocity_error_xy_mps 判课程时要除以步数，不是秒数。
✧ 它怎么读数据
  • 只读本机 logs/rsl_rl/ 下的 events.out.tfevents*，不联网、不上传。
  • 第一次读一个大的 run 要十来秒（60 MB 左右），之后走 logs/kline_cache/，打开基本是秒开。
  • 训练还在写时，同一个文件最多每十几秒重读一次，避免每个请求都重扫一遍。
  • 解析在后台线程做，页面上会显示「正在解析 event 文件」，不会把界面卡住。

⚠️ 所有数字都是本机日志里的原始值，可能因为日志没写全、nan guard 拦截、中断续训而缺段； 做重要判断前请回 TensorBoard 或训练日志核对 (｡•́︿•̀｡)
