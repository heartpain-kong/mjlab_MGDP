# 与原 MGDP 方案的差异

本仓库**沿用了官方 MGDP 的深度感知骨架**（U-Net 双分支、64 维深度特征 + 32 维高度特征），
但改了**感知训练方式、控制器输入和越障课程**。

最大的训练差异：官方发布代码在运动训练过程中仍用当前采样更新感知模型（两阶段都可更新），
本仓库**先离线预训练感知，再冻结它训练 PPO**。

> 下表"官方 MGDP"指 `arclab-hku/MGDP` 公开源码（`legged_gym` 版，提交 `f43139d`）；
> "本仓库"指当前 `main` 分支。服务器上的旧部署包可能使用不同配置。

| 对比项 | 官方 MGDP | 本仓库（LgDog1 MGDP） |
|---|---|---|
| 仿真平台 | Isaac Gym + Legged Gym，自带 Warp 深度传感器，支持多种四足形态 | MuJoCo / mjlab + Warp 射线，围绕 LgDog1 的关节控制与比赛地形配置 |
| 深度输入 | 默认 Warp 相机 **120×120** → 缩到 **16×16**，取 2 帧；水平视场 67°、下俯 30° | D435i 任务直接采样 **32×24**，取 2 帧；视场 87°×58°，深度按 **0.2–3.0 m** 处理，仿真安装下俯 **22°** |
| 感知网络 | U-Net 双分支，深度编码 64 维、高度编码 32 维，深度分支 **MaxPool** 下采样 | 相同特征维度与双分支结构，深度分支改为**可学习的步长卷积**下采样 |
| 感知怎么学 | 两个阶段都可随仿真采样更新感知；Stage 2 默认加载 Stage 1 权重继续更新；感知与 PPO 分别优化 | 随机小动作采集深度/高度序列（每段 8 步），离线训练加入 **Sobel 边缘损失**与 **GRU 时序损失**；PPO 阶段只读**冻结的 64 维特征** |
| 策略看什么 | 45 维本体观测 + **7 维状态估计**（机身速度、四足高度）+ 64 维视觉特征 = **116 维** | **4 帧 × 47 维**本体观测（188）+ 64 维视觉特征 = **252 维**，省去单独训练的状态估计器 |
| 怎么练越障 | Stage 2 用通用跑酷地形 + 地形自适应奖励，支持换机器人微调 | 按比赛障碍设**八档课程**；技能 V5 中高墙先练第一墙、沟槽先练第一组、绕桩逐档延长；回放可独立选择完整赛道验收 |

一个实现细节：官方论文把 GRU 写成融合深度与高度两路特征，但**公开源码**实际把深度编码器的
`visual_token` 送入 GRU，高度图用于重建/对比监督，同时作为 critic 的特权输入。
本仓库同样走"深度特征进 actor"的路线。

## 对翻墙、跨沟、踩桩意味着什么

最值得关注的是**感知训练看到什么**：

- 官方感知会持续看到策略实际运动时采到的画面（含起跳、落地、贴桩沿等视角）；
- 本仓库的感知主要从**随机小动作采集**的序列学习，随后冻结。

因此这些关键视角是否被采够，会直接影响 PPO 能用到的信息。这是训练设计上的差异，
现有代码**无法单独判定**它是不是低通过率的主因——需要通过"换采样分布重训感知"做对照实验。

相关代码：

- `scripts/pretrain_mgdp.py` — 离线感知预训练采集与训练
- `src/tasks/velocity/mdp/mgdp_perception.py` — 感知损失（重构 / Sobel 边缘 / 对比 / 时序）
- `src/tasks/velocity/config/lgdog1/mgdp_env_cfg.py` — 深度采样与感知接入

## 相机参数一致性（已修复）

此前存在一处实际不一致：**D435i 仿真安装下俯 22°，但相机契约元数据仍写 20°**。
回放与部署会校验相机契约，旧的 20° 感知权重可能因此被拒绝。

现在 `src/mgdp_depth.py` 的 `pattern_contract()` 直接取 profile 的
`pitch_down_deg`（22°）生成 `mount` 名称与 extrinsics，仿真与元数据保持一致。

> profile 名 `d435i_edge16_down20` 是历史命名（早期 16×16/20° 时期），保留它是为了兼容旧配置；
> 当前实际参数以 `pattern_contract()` 输出为准。

官方权重若要迁移到本仓库，需要做兼容性适配：两套策略输入维度不同（116 vs 252），
且当前深度编码器多了两层可学习下采样参数。
