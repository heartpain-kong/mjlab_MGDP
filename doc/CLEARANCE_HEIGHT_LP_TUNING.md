# 标准HIM：连续摆动净空和LP参数

2026-10-28。此说明针对 `LgDog1-Rough-Blind-HIM-Standard`。新训练默认3帧历史，输入141维；这里没有改变PPO/HIM网络。文中权重是待GPU训练验证的初始设置，不是已经证实最优的超参数。

## 为什么开抬脚后可能变怪

旧标准HIM抬脚代价在每个非接触控制步计算 `abs(足端相对地面高度-0.10)*足端水平速度`。它存在两个可疑激励：自然起脚/落脚也偏离固定10cm；降低摆脚水平速度能减少代价。强权重还会让低台阶与正常平地都追求同一高度。代码能确认这些激励，但缺少本轮开启后的轨迹，不能断言它们是异常动作的唯一原因。

不能直接照搬HIMLoco的-0.01：其抬脚定义使用机体坐标中的脚位置，与我们的足端相对地面净空不同。来源：[官方HIMLoco reward实现](https://github.com/InternRobotics/HIMLoco/blob/main/legged_gym/legged_gym/envs/base/legged_robot.py)。

## 连续摆动净空（替换上一版落地峰值方案）

标准HIM的 `foot_clearance` 仍绑定 `blind_mdp.feet_clearance_swing`，但已经移除落地峰值缓存、最短滞空过滤和落地步的除dt结算。上一版方案会让不抬脚、短促碎步或落地前终止绕过代价，还会把惩罚集中在一次触地上。这些是实现中的激励漏洞，不代表已经定位所有实际步态问题。

新实现每个控制步都计算，跟随现有 `foot_gait` 的period、offset和支撑比例，避免两套步态时钟冲突。设摆动进度为u：

```text
h_required = target_height * sin(pi * u)^2
shortfall = max(h_required - foot_clearance - tolerance, 0) / target_height
cost = mean_over_four_feet(valid_swing * min(shortfall^2, 1))
```

起脚和落脚时目标接近0，摆动中段平滑升到6cm，容差1cm。不要求整个摆动期悬在固定高度；已经足够高时该项归零，不奖励继续抬高。不会用刚性高度上限惩罚下台阶时脚下地面降低产生的净空。

**实际触地不会将代价屏蔽**：如果已到预期摆动中段但脚还踩地，仍有短缺代价。去掉足端水平速度乘子，降低摆脚速度也不能直接减少同一高度/相位下的误差。站立指令、支撑相位和无效射线不计入。按四足固定数量平均，单步原始代价在0到1之间；仅由RewardManager进行一次dt缩放，不再制造落地冲量。

该项是与已有步态同步的软引导，不代表接触相位真值；复杂地形上合理延长支撑也可能受到它的约束，所以保持小权重并做固定地形对照，不保证开启后必然改善。

默认权重仍为 **0**，启用对照可先用 **-0.2**；新公式与旧公式的权重不能等同。工作台JSON只需：

```json
{"target_height":0.06,"tolerance":0.01}
```

period、offset、stance_fraction自动从当前 `foot_gait` 配置同步。旧峰值方案的 `max_height`、`min_air_time` 已不适用，如面板存有这些字段需删除，配置会在创建物理环境前给出迁移提示。

此函数没有每只脚的峰值/滞空历史，仅缓存固定相位偏移；局部reset后直接使用新episode计时，不遗留旧摆动状态。TerrainV4、温和HIM和普通PPO保留各自原有抬脚公式。

## base_height已撤回

按用户要求，移除新增的base_height奖励、公式、工作台奖励条目和机身高度监控。没有将它作为0权重条目保留。足下射线继续用于原来的相对净空和critic标签，actor仍无地形扫描。

上一轮顺带调整的 `feet_air_time.threshold` 也恢复原来的0.4秒，这次集中验证抬脚公式。工作台保留“摆动净空/有效摆动”监控，以有效摆动样本的高度分子除以有效样本比例，不再显示落足峰值。权重0或旧run没有新指标时显示—。

## LP怎么填

以下只适用于工作台显示 **LP稳定版v2** 的代码；旧v1只填相同数字不等价。完整统计协议见 [LP_ACRL_INTEGRATION.md](LP_ACRL_INTEGRATION.md)。

| 工作台参数 | 建议初值 | 目的 |
|---|---:|---|
| LP温度 | 2.0 | v2已按最大回合时长归一并平滑LP；不能与v1原始回报差温度直接比较 |
| 基础地形比例混合量 | 0.5 | 保留类型覆盖，平地至少10%，上/下台阶各至少10%，其余各至少5% |
| 单任务概率上限 | 0.25 | 避免V28式90%单任务占比；基础分布有更大单任务时上限自动提高 |
| 进度平滑系数 | 0.25 | 降低一次窗口回报波动的影响 |
| 概率更新系数 | 0.2 | 每次只向新目标分布移动20% |
| 每任务最少回合 | 32 | 样本不足继续积累，不填0回报 |
| 收集窗口 | 100仿真秒 | 之后等一个完整回合时长；20秒回合时约120秒更新一次 |

先固定速度包络x=(-0.3,0.5)，地形行数10、上限1.0、rollout50，冻结其他奖励。做抬脚消融时比较权重0和-0.2，其他参数、种子、样本预算保持一致。抬脚函数定义改变后，应另开实验；新课程签名会清除不可比的旧LP统计。此前V28是6帧模型，不能直接resume为本轮3帧模型。

如果概率仍抖动，可只把概率更新系数0.2降至0.1，观察多个完整窗口；如果各类地形覆盖不足，可只把基础混合量0.5升至0.7。不要同时提高速度、地形难度、抬脚惩罚与LP激进程度。

验收按固定地图、固定指令的通过距离、未摔时长、速度误差、动作裁剪以及高度曲线进行。机身高度合理或地形level高，都不代表已经通过楼梯。应先验5cm再测10/15cm，后续扩到多个随机初始状态和种子。

LP依据：[Scaling Rough Terrain Locomotion with Automatic Curriculum Reinforcement Learning](https://arxiv.org/html/2601.17428v1)，式6–7；这里的平滑、基础混合、概率上限和启动窗口结算是LgDog工程扩展。

本次全量CPU回归181项：180项通过、1项跳过。重点覆盖不抬脚/触地抖动不能屏蔽代价、起落脚目标平滑、零指令/射线失效、地面平移、局部reset、控制dt积分一致、实际RewardManager仅缩放一次，以及修改foot_gait后的相位同步。工作台净空数据显示与缺失值处理通过逻辑检查。GPU收敛和实际步态改善尚未验证；更换代码后重启工作台及训练才生效。
