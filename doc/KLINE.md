# 曲线终端：把 TensorBoard 曲线当行情看

`src/kline/` 是工程里第二个本地网页面板，只做一件事：**把 `logs/rsl_rl` 里的 TensorBoard
标量曲线，按训练步长切成蜡烛图**，外面套一层行情终端的皮（红涨绿跌、均线、波动柱、盘口、逐点流水）。

老实看 TensorBoard 很枯燥吧？所以才做成这副样子的。

```bash
python lgdog.py kline                 # 默认端口 8766，自动开浏览器
python lgdog.py kline --port 9000
python lgdog.py kline --logdir /path/to/archive/logs/rsl_rl   # 再加一个归档目录，可给多次
python -m src.kline --no-browser      # 等价入口，不打开浏览器
```

打开 **http://127.0.0.1:8766**。服务只监听 `127.0.0.1`，没有联网请求，没有写文件接口。

## 它到底把什么变成了什么

| 行情里的词 | 这里指什么 |
|---|---|
| 城市 / 轮次 | 一个 run 目录（`logs/rsl_rl/<实验>/<时间戳_run名>`） |
| 品种 / 指标 | 一条 scalar，比如 `Train/mean_reward` |
| 价格 | 这条 scalar 的值 |
| 分时 | 原始记录点连成的曲线（点太多时按顺序等分取均值，形状不变） |
| 一根蜡烛 | 一段训练步窗口：开盘 = 窗口第一个值，收盘 = 最后一个值，影线两端 = 窗口内最高/最低 |
| 短K / 中K / 长K / 全程K | 窗口宽度的四档预设，按这个 run 的总步数取整成 1/2/5×10ⁿ 步 |
| 均线 MA5/10/20/60 | 最近 N 根蜡烛收盘价的滑动平均 |
| 波动柱（成交量） | 每根蜡烛的波动口径，顶栏可切：窗口振幅 / 标准差 / 记录点数 / 相对变化 |
| 基准线（灰虚线） | 图上第一根蜡烛的开盘值，相当于「昨收」 |
| 「未收盘」的最后一根 | 训练还在写日志时，最后一个窗口没满，那根蜡烛会继续长 |

## 页面上的东西

| 位置 | 内容 |
|---|---|
| 顶栏 | 搜索（轮次 / 指标）、刷新间隔、涨跌颜色（红涨 / 绿涨）、波动柱口径、回放、术语、刷新 |

| 中栏 | 行情头（最新值、涨跌、20 格统计）+ 周期页签 + 主图 + 副图 |

## 数据怎么读的

1. 扫 `--logdir`（默认 `logs/rsl_rl`）下最多三层的目录，找出**直接包含 `events.out.tfevents*`** 的目录当 run。
   同一份 run 可能既在工程 `logs/` 又在归档目录里 —— 按「标签 + 文件总大小」去重，**靠前的数据源优先**。
2. 解析用 TensorBoard 自己的 `EventAccumulator`（`size_guidance={'scalars': 0}`，即全量保留）。
   60 MB 左右的 event 文件第一次要十几秒，所以：
   - 解析放在**后台线程**，页面先显示「正在解析 event 文件…」，不阻塞其它请求；
   - 结果写进 `logs/kline_cache/<run id>.lgk`（gzip，头部记着源文件的路径 / mtime / 大小），下次打开基本秒开。
3. 训练还在写时，同一个文件最多每 15 秒重读一次（`Store.ensure(max_age=...)`），
   不会每个前端请求都重扫几十 MB。
4. 只有 `tensorboard` 是可选依赖；没装的话页面照样能开，只是会在状态栏明确写「读不了 event 文件」。

### 两个踩过的坑（改代码前务必看）

- **`*/time` 这类 tag 的 step 是秒，不是迭代数。** `Train/mean_reward/time` 的 step 能到几万，
  如果把它算进「步数范围」，窗口宽度会整体算大几十倍，一屏只剩一根蜡烛。所以
  `Run.bounds()` 算首末步时**跳过 `*/time`**，wall time 仍然取全部。
- **缓存是按「所有 step / 所有 value / 所有 wall」三段排列存的。** 每段的偏移必须按
  单条数组的长度（`n * 8`）累加；早先按 `n * 24` 算，多 tag、长度不等的 run 读回来会串位，
  表现为 `IndexError: array index out of range`。现在解码前会校验总长度，对不上就当缓存失效重解析。

## 接口

全部只读，返回 JSON（导出接口返回 CSV）：

| 路径 | 作用 |
|---|---|
| `GET /api/state` | 数据源、轮次清单（轻量元信息）、关键指标列表 |
| `GET /api/run?id=` | 某个轮次的完整元信息 + 全部指标（含中文名/分组/方向）+ 四档窗口方案 |
| `GET /api/series?id=&tag=&mode=k\|line&bucket=&max_points=` | 蜡烛或分时点，附带首末值、点数、最近 240 条 tail |
| `GET /api/overview?tags=a,b,c` | 所有轮次在若干指标上的最后一个记录点（自选列表、指数条、对比表用） |
| `GET /api/health?id=` | 每个指标的数据体检结论（NaN、台阶、断档、常量占位…） |
| `GET /api/export?id=&tag=&bucket=` | 按窗口导出 CSV |
| `GET /api/dict` | 指标词典（`labels.py` 的注册表 + 未注册 tag 的兜底） |
| `GET /api/rescan` | 重新扫目录，不用重启服务 |

| 文件 | 作用 |
|---|---|
| `src/kline/store.py` | 扫目录、解析 event、磁盘缓存、按需后台加载 |

| `tests/test_kline.py` | 窗口聚合、缓存往返、HTTP 接口、体检规则的回归测试 |

## 看曲线时的三个提醒

1. **跨轮次比较务必取同区间。** 这套任务的指令范围课程在 iteration 5000 附近放宽，
   之后误差类指标会台阶式变差 —— 那是任务变难了，不是策略退化。
2. **mjlab 的 metrics 不做 dt 缩放**，记录的是每步原始值之和；
   拿 `velocity_error_xy_mps` 判课程要除以步数，不是秒数（见 [训练归档说明](../../数据/训练归档说明.md)）。
3. **「涨」只表示这个数在变大，不表示变好了。** 误差、损失、失败率涨了都是坏事。
   指标词典里标了「越大越好 / 越小越好」，拿不准就看那里。
